# Feature Specification: Provider 模型统一接入

**Feature Branch**: `039-provider-model-integration`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: US1

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按名称选择模型供应商 (Priority: P1)

作为企业开发者，我希望通过供应商名称选择模型，让 Agent 使用统一的对话能力而无需了解各家模型协议差异。

**Why this priority**: 没有稳定的模型接入，后续 ReAct 循环和所有 Agent 能力都无法运行；显式路由也避免多供应商配置时请求发错模型。

**Independent Test**: 配置两个可用供应商，分别按名称发起请求，验证响应格式一致且请求只到达指定供应商。

**Acceptance Scenarios**:

1. **Given** 已配置并启用供应商 `provider-a`，**When** 请求指定 `provider-a`，**Then** 系统调用该供应商并返回统一格式的响应。
2. **Given** 已配置 `provider-a` 与 `provider-b`，**When** 请求指定 `provider-b`，**Then** 系统不会调用 `provider-a`。
3. **Given** 请求引用不存在或已禁用的供应商，**When** 发起请求，**Then** 系统返回明确的配置错误且不发出模型请求。

### User Story 2 - 安全配置与运行时维护 (Priority: P2)

作为运维人员，我希望安全地新增、修改、启用或停用供应商，并在凭证缺失时获得可诊断提示。

**Why this priority**: 企业需要在不修改 Agent 指令的情况下切换模型，并确保密钥不进入代码、日志或接口响应。

**Independent Test**: 通过管理入口维护供应商配置，验证启停和更新立即影响路由，检查所有输出均已脱敏。

**Acceptance Scenarios**:

1. **Given** 供应商配置使用环境变量或密钥引用，**When** 查询配置，**Then** 返回连接信息但不返回明文凭证。
2. **Given** 供应商被停用，**When** Agent 请求该供应商，**Then** 请求被拒绝并提示可用供应商。
3. **Given** 供应商基础地址或凭证更新，**When** 下一次请求到达，**Then** 使用更新后的配置，无需修改 Agent 任务指令。

### Edge Cases

- 供应商名称为空、重复、包含路径分隔符或超出长度限制时，配置必须被拒绝。
- 供应商返回超时、限流、协议错误或空响应时，系统必须返回稳定错误，不泄露请求凭证。
- 多个请求同时更新同一供应商时，最终配置必须可确定，不能产生部分更新。
- 未配置任何供应商时，服务可以启动，但模型请求必须返回明确的配置提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每个供应商维护唯一、稳定且可验证的名称。
- **FR-002**: 系统 MUST 根据请求中的供应商名称执行显式路由，并提供统一的模型请求与响应格式。
- **FR-003**: 系统 MUST 支持至少两个供应商同时启用，且每次请求只调用被选中的供应商。
- **FR-004**: 系统 MUST 支持供应商配置的创建、读取、更新、启用和停用。
- **FR-005**: 系统 MUST 在供应商不存在、停用、不可达或凭证缺失时返回可诊断错误。
- **FR-006**: 系统 MUST 从环境变量或企业密钥体系读取凭证，禁止明文凭证出现在代码、配置、日志或响应中。
- **FR-007**: 系统 MUST 在供应商连接信息变更后，使后续请求使用最新配置。
- **FR-008**: 系统 MUST 为每次模型请求提供可关联的调用标识，供后续审计和故障定位使用。
- **FR-009**: 系统 MUST 保持模型供应商差异对 Agent 指令透明，切换供应商无需修改 Agent 配置语义。

### Key Entities *(include if data involved)*

- **Provider**：供应商名称、协议类型、基础地址、模型标识、凭证引用、启用状态和更新时间。
- **Model Request**：供应商名称、消息、模型参数、调用标识和请求时间。
- **Model Response**：统一文本或工具调用结果、用量摘要、状态和错误信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 配置两个供应商后，100% 的路由验收请求到达指定供应商，零请求误路由。
- **SC-002**: 95% 的正常模型请求在 5 秒内返回统一格式结果（不含供应商网络波动）。
- **SC-003**: 100% 的凭证缺失、供应商停用和不可达场景返回明确错误，且不返回明文凭证。
- **SC-004**: 运维人员可在 5 分钟内完成供应商新增、停用和切换验证，无需修改 Agent 指令。
- **SC-005**: 100% 的模型请求具有可关联调用标识，可用于后续审计查询。

## Assumptions

- 首个版本支持项目已选定的主流文本模型协议；新增协议通过供应商适配层扩展。
- 供应商密钥由部署环境或企业密钥系统提供，功能本身不负责发放密钥。
- 本特性只覆盖模型接入和路由，不实现 ReAct 循环、工具执行、流式输出或自动故障转移。
- 管理入口沿用现有 OryxOS CLI/Web 能力；本特性提供统一服务语义。
