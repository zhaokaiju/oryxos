# OryxOS SaaS 多租户行业调研与定位

## 一、研究结论

OryxOS 当前定位是企业私有部署的 Agent OS；SaaS 化不是把多个用户简单放进同一个数据库，而是把“企业可控、可审计、数据不越界”的能力扩展到多个租户共享的平台。SaaS 版本必须同时满足三类要求：租户隔离、平台运营效率和企业级合规。

## 二、市场空白

现有 Agent SaaS 多数强调模型调用、工作流和快速试用，企业真正关心的租户级数据隔离、组织权限、审计留证、密钥归属、区域部署和迁移退出往往是后置能力。传统 SaaS 多租户方案也通常假设业务数据是普通 CRUD 数据，无法直接覆盖 Agent 的 Prompt、Skill、Memory、Tool 调用和模型凭证等高风险资产。

OryxOS 的机会是把现有 Agent Runtime 的安全边界提升为租户边界：每个租户拥有独立的 Agent、Skill、Memory、Knowledge、Provider、会话和审计视图；平台只管理基础设施，不读取租户业务内容。

## 三、目标客户与场景

- 服务多个企业客户的托管 Agent 平台
- 集团内按子公司、部门或项目隔离的 Agent 平台
- 需要独立密钥、独立审计和区域存储的金融、政务、医疗、电信和能源企业
- ISV 将 OryxOS 作为行业 Agent 能力底座

## 四、SaaS 价值

1. **隔离**：一个平台承载多个租户，租户间数据、配置、执行和管理权限不可越界。
2. **运营**：平台统一升级、监控、计量和资源管理，租户独立配置业务能力。
3. **可控**：租户可管理自己的 Provider、Tool、Skill、Agent 和审计记录。
4. **可迁移**：租户能够导出自己的配置、知识和审计数据，避免平台锁定。
5. **可扩展**：同一运行时既支持共享 SaaS，也支持专属实例和混合部署。

## 五、必须解决的行业问题

- 身份：平台管理员、租户管理员、成员、审计员和只读用户的权限边界
- 隔离：数据库查询、缓存、文件路径、向量索引、消息队列、日志和指标的租户标签
- 凭证：Provider 密钥由租户控制，平台运维不能读取明文
- 审计：记录谁在何时以哪个租户身份调用了哪个 Agent、Tool 和模型
- 资源：并发、Token、存储、请求频率和成本的租户配额
- 合规：数据驻留、保留期限、删除证明、备份恢复和安全事件响应
- 退出：完整导出、删除和专属实例迁移

## 六、OryxOS SaaS 定位

OryxOS SaaS 是“多租户 Agent Runtime 平台”，不是通用低代码工作流平台，也不是替代企业业务系统的 SaaS 应用。它继续坚持：自实现 ReAct、标准协议接入、Skill 能力沉淀、私有数据边界和全链路审计。

## 七、演进方向

第一阶段完成单集群多租户基础和强制隔离；第二阶段提供专属租户实例、区域化部署、计量计费和企业身份集成；第三阶段提供跨区域容灾、Agent 市场和租户可携带的知识资产。
